# 顶层设计捋清文档（UNIFIED_DESIGN）

日期：2026-08-25
性质：**二次开发前的概念清算**。本文档回答四个问题：名词关系、统一蓝图、组件去留、
约束与验收。在本文档确认之前，暂停一切新功能开发。

## 一、名词关系（谁是谁，一句话说清）

| 名词 | 是什么 | 和我们的关系 |
|---|---|---|
| **PaSa**（字节） | Crawler+Selector 双 Agent 论文爬取方法，**读正文、按章节抽引用**；AutoScholarQuery 数据集和 recall@20/50/100 评价口径的作者 | **唯一对标方法**（已定） |
| **SPAR**（另一团队） | RefChain 查询分解+引用扩展，F1=0.38 那篇论文 | 我们最初的主干参考；其搜索树/排序公式已吸收，**今后不再跟着它走** |
| **asta-bench**（AllenAI） | PaperFindingBench：S2 ID + LLM 判卷的另一种评测 | 备用第二验证集，暂不接入 |
| **我们的项目** | 以 PaSa 为纲的检索系统 | 已有的数据协议/成本计量/测试底座全部保留复用 |

一句话：**PaSa 和 SPAR 是两个不同团队的同类方法，赛题都引用了。以前我们混着学导致口径乱，现在专攻 PaSa 一条线。**

## 二、统一蓝图（唯一的顶层流程）

以 PaSa 原版流程为纲，角色只有两个（Crawler 负责探索，Selector 负责判断）：

```
用户问题
 ① [Crawler·generate_query] 生成 5 条检索式（固定 prompt 模板约束）
 ② arXiv/S2 检索 → 跨源合并去重（已有组件）
 ③ [Selector·get_selected] 对每篇打 select_score（读标题+摘要，固定模板）
 ④ 对高分论文：本地下载 PDF → 抽正文 → 切章节（无 API，本地为准）
 ⑤ [Crawler·select_section] 挑出与问题相关的章节（固定模板）
 ⑥ 从相关章节的引用文本中解析被引论文 → 逐条查回
 ⑦ [Selector] 给新论文打分 → 高分入池，回到 ④（共 2 层，PaSa 同款层数）
 ⑧ 输出：select_score>0.5 的集合 + 排序 + 成本账单
```

关键设计原则（回应"瞎整"批评）：
- **每个 LLM 环节都有固定 prompt 模板**（照 PaSa 的 4 个模板改造：generate_query /
  select_section / get_selected / get_value），不允许自由发挥；
- **正文是召回的主引擎**，标题/摘要只做初筛——不再用"标题摘要打分→发散"的瞎猜模式；
- **顺藤摸瓜只摸相关章节里的瓜**，不是整篇参考文献列表。

## 三、组件去留裁决表

| 现有组件 | 裁决 | 理由 |
|---|---|---|
| 数据协议（PaperDoc/身份/去重/错误） | **保留** | 底座资产，230+ 测试覆盖 |
| 检索层（Provider/RRF 融合） | **保留，参数对齐 PaSa**（初始查询 2→5、扩展宽度 8→20、并发提高） | 直接复用 |
| 词法+LLM 融合打分 | **保留，降级为初筛** | 正文精读后的 Selector 判断才是终审 |
| 引用扩展（OpenAlex 参考文献列表） | **保留为兜底，主路改为 PaSa 式"正文-章节-引用"** | 核心二次开发点 |
| 全文层 fulltext.py（本地抽取） | **升为主力**，与老师工具的本地模式同原理；API 模式仅扫描版 PDF 可选 | 口径统一：本地为准 |
| **P3 五 Agent 圆桌** | **降级为工作流协议层**（回放/审计），退出效果主路径 | 实测不增检索能力；且无 per-agent skill 的圆桌=流水线换皮。若未来要真 Agent 化，前提是每个角色有固定 prompt 模板+专属工具+独立验收，目前不做 |
| P2 管线 | 保留为"无 LLM 降级模式" | 兜底 |
| 评测 | **PaSa 官方口径为主**（recall@20/50/100 宏观标题匹配），F1@10 为辅 | 已实现（pasa_metrics.py） |

## 四、口径统一清单（不再摇摆）

1. **正文获取**：本地抽取（pymupdf）为准。老师的工具本地模式与我们的 fulltext.py
   同原理，工具保留作 GUI/备用。**"必须 API"的说法作废**（converter.py 默认
   `use_api=False`，此前判断有误，已更正）。
2. **评测口径**：PaSa 官方 recall@20/50/100 为主指标；F1@10 保留供对照。
3. **Agent 口径**：只有 Crawler/Selector 两个角色，各有 4 个固定 prompt 模板中的
   对应约束；输出必须 JSON；失败降级路径固定。
4. **数据集**：AutoScholarQuery（官方参考库 1 原版）为准，50 题为标准验收批次。

## 五、验收标准（明确的数字和门槛）

| 阶段 | 内容 | 验收 |
|---|---|---|
| S1 正文链路 | 下载→切章节→引用解析，每步独立单测 | 新增 ≥10 项测试全绿；扫描版/无 PDF/解析失败全部优雅跳过 |
| S2 双角色接入 | 4 个固定 prompt 模板落地 + JSON 校验 + 降级 | 模板内容锁定入测试；LLM 失败回退词法不产生假分 |
| S3 主管线切换 | ~~PaSa 式管线跑 50 题~~ 已被 5 题哨兵制度取代（见 HANDOVER §7；50 题产物只读存档） | 与存档基线（recall@20=**0.298**，tree-n50-v2* 两段合并，2026-08-25 审计复核）同题配对比较 |
| **里程碑 1** | recall@20 ≥ 0.30 | 已过线（0.298 为存档值；后续改动以哨兵同题胜负表为准） |
| **里程碑 2** | recall@20 ≥ 0.40 | 接近 PaSa 公开水平 |
| 效率红线 | 每题 ≤ 60 次 API 调用、≤ 5 万 token、≤ 3 分钟 | 超线必须先优化预算再谈效果 |

## 六、执行顺序（确认本文档后启动）

S1 → S2 → S3 → 里程碑冲刺。当前正在跑的 50 题大盘完成后作为**基线存档**，
此后所有改动都对这个基线做 A/B。
